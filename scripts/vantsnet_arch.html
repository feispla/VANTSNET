OPCIÓN 2 · DIAGRAMA DE ARQUITECTURA

VANTSNET

Arquitectura de una red de estadísticas gaming: APIs oficiales de cada juego, colectores con colas y caché, núcleo backend con API propia y una capa de presentación multi-juego.

github.com/feispla/VANTSNET
Flujo de datos: de arriba hacia abajo
Estadísticas multi-juego con una sola API
Capa 1 Fuentes de datos APIs oficiales — solo fuentes autorizadas por los ToS de cada juego
Riot Games API
Valorant · LoL · TFT — OAuth 2.0 + API key de desarrollo/producción
Bungie.net API
Destiny 2 — OAuth por usuario con refresco automático de token
Steam Web API
CS2 · Dota 2 — Steam Web API Key, perfiles y partidas
Epic Manifest API
Fortnite — manifiestos para detectar parches y metas
Data Ingest
Servidores de juego envían POST JSON al final de cada partida
↓ consume APIs oficiales · respeta rate limits
Capa 2 Ingesta y colecta los "collectors" — donde VANTSNET hace el trabajo pesado
Workers de colecta
Colas de tareas asíncronas (Redis Queue / Horizon) — refrescan perfiles
Rotación de proxies IPv6
Evita bloqueos por IP — miles de IPs salientes desde un /64 IPv6
Caché de resultados
TTL ~5 min por consulta — reduce llamadas a las APIs oficiales
Endpoint /api/ingest
Valida y normaliza el JSON de partidas que reportan los servidores
↓ partidas normalizadas + perfiles actualizados
Capa 3 Núcleo backend el corazón de VANTSNET — API propia + persistencia
API REST propia
Autenticación por clave propia — VANTS-Api-Key en cada petición
PostgreSQL
players · matches · match_player_stats · leaderboards
Redis
Caché de respuestas + colas de workers + locks
Scheduler
Tareas programadas: reintentos, rankings nocturnos, limpieza
↓ sirve estadísticas vía API interna
Capa 4 Presentación un solo código base, un tema por juego (patrón vue-theme-loader)
